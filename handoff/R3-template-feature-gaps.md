# R3: app features needed for the historical templates (next development)

Status 2026-09-24. These gaps turned up while building `TemplateExamples/Historical1950/` from the sourced reference (`docs/historical-reference/`). Each gap forced a workaround or left out behaviour the sources describe.

**Status:** proposals only, none started. They are **not** part of a 0.6 release: nothing has been tagged, and the version is still `0.5.0-alpha`.

Rough priority is top to bottom. Sizes: S = under a day, M = a few days, L = larger.

## F1. Respawn a linked flight on a cooldown (Template Builder) — M

**Problem.** `generate_template` forces `BringUp::Activate` whenever wingmen are linked to a lead (`template.rs`, `let bring_up = if linked_wingmen { Activate } …`). So `allow_multiple_spawns` / `spawn_cooldown_min` are silently ignored for any real flight.
- History it blocks: the F-80 air alert launched **a new flight every 20 min** [S9 p.101].

**Want.** A linked flight that can come back after a cooldown. Either:
- spawn the lead and have wingmen follow after spawn, or
- run a Deactivate → Activate cycle driven by `COOLDOWN` for Activate-mode groups.

**Also.** Surface a UI warning today when the options are set but will be ignored.

**Acceptance.**
- A 4-ship with linked wingmen and multiple spawns on gets a working `COOLDOWN` timer (> 0).
- It comes back in the editor after cleanup.
- A test covers it.

## F2. Loader round-trip for every spawn layout — S

**Problem.** `load_template` does not recognise the **Pairs** `PlaceLayout`. It warns "Unit positions did not match a Template Builder formation (about 37 m off)" and falls back to finger-four. It is worth checking Echelon, Line abreast and Column too.
- Workaround used: the 2+2 historical templates spawn in finger-four with `per_group = 2`.

**Acceptance.**
- For every `PlaceLayout::ALL` × per-group 2/4/6, a file made by `generate_template` reloads with the same layout and no warning.
- A test covers the whole matrix.

## F3. "Break off after losses" event — M

**Problem.** There is no Template Builder hook for "when N of this group are down, Force Complete / RTB the rest".
- History it blocks: on 27 Jun 1950 the 8 Il-10s broke off after losing 4 [S9 p.35]. This kind of rule is common in the reference.
- The machinery partly exists: `DeathCount` is already generated for cooldowns.

**Want.** A group-level event, "on N destroyed → Force Complete / Mission Complete", editable in the orders tree.

**Acceptance.**
- A generated file has a counter over all group entities that pulses the group's `MISSION END ORDERS` at N.
- `inspect_plan` still accepts the file.

## F4. Cross-template trigger hooks — M

**Problem.** Templates are self-contained. Linking one template's events to another's start has to be wired by hand in the editor.
- History it blocks: North Korean Yak raids were timed for when the F-80 patrol ran short of fuel [S9 p.121]. That is "start raid B when patrol A completes".

**Want.** Named external in/out MCUs on every template (for example `EXT START` and `EXT DONE`), and a way in Exclusive Activation or Map to connect A's `EXT DONE` to B's `EXT START` with a delay.

**Acceptance.**
- Connecting two generated templates produces a timer from A's done hub to B's bring-up.
- Both files still pass `inspect_plan`.

## F5. Date-aware aircraft availability warning — S–M

**Problem.** Nothing stops an anachronistic type for the mission date. The shipped Eastern random packs mix **La-11 / Yak-9P / MiG-15**, but:
- no La-9 or La-11 flew in 1950 (La-9 first appears Nov 1951 [S9 p.437]; La-11 Apr 1953 [S9 p.686]);
- MiG-15s first appear 1 Nov 1950 [S9 p.241].

**Want.** An "in theatre from / to" table for each catalog type, seeded from reference §2.2, §3 and §9. Map mode and Fighter Pack show an orange warning when a chosen type is outside the Map date.

**Acceptance.**
- Picking La-11 with a 1950 Map date shows a warning that cites the date.
- The table is unit-tested.

## F6. Headless template generation (CLI or library target) — M

**Problem.** The crate is a single binary, so R1's historical templates were generated by a scratch crate that `#[path]`-includes the non-UI `src/` modules plus `build.rs`. The scratch crate lives in a temp folder and is not reproducible from the repo.

**Want.** One of:
- a `lib` target (or `src/lib.rs` re-exporting the non-UI modules) plus a small `bin`/example, e.g. `cargo run --example gen_templates -- spec.toml out/`;
- a `--generate-template <spec>` CLI flag.

**Also.** Add the historical templates as regression fixtures.

**Acceptance.**
- `TemplateExamples/Historical1950/*.Group` can be regenerated byte-for-byte from a checked-in spec.
- `cargo test` compares them.

## F7. Sensible waypoint speed without the UI — S

**Problem.** `TemplateOptions::default().waypoint_speed` is **100 km/h**. The UI replaces it with `model_spec::suggested_waypoint_speed_kmh(...)`, but any other caller of `generate_template` (F6, tests, other modes) writes a 100 km/h waypoint for aircraft.

**Want.** Treat `waypoint_speed <= 0` as "derive from the seats" inside `generate_template`, and default it to 0.

**Acceptance.** A headless 4-ship F-80 template gets the cruise-derived speed (660 km/h in the current data).

## F8. Night defended-area template (searchlights) — M

**Want.** A Template Builder preset or Army Generator type for the searchlight guidance in reference §8.9:
- 4–8 `ge1942a` lights in pairs along an approach line, plus `ks12` 85-mm guns on the same line;
- optional 2–4 night MiGs;
- zone-activated, night only.

**Also.** Reuse the K-13/K-14/K-15 airfield pattern: one light driven by two AttackArea commands, `VERTICAL_SearchLightArea` at about 3,000 m and `SearchLightArea`.

**Known limit.** The catalog has no Eastern searchlight model.

**Acceptance.**
- The generated group puts every light within the sourced reach of a bomber at 5,490 m: about 7.3 km from the approach line.
- It passes `inspect_plan`.

## F9. Per-element altitude in a Template Builder flight — S

**Problem.** Wingmen match the lead's altitude (the P7 rule). A 2+2 "low element hunts, high element covers" flight [S9 p.268] therefore needs two separate leads.
- The Fighter Pack already does a 2-low / 2-high split, but Template Builder can't.

**Want.** An optional altitude step for the second element.

**Acceptance.** A 4-ship with a +1,500 m element step writes seats 3–4 at lead + 1,500 m, capped at their own ceiling.

## Not features: things to verify in game

- The six Historical1950 templates have been validated in the app code only (`load_template`, `inspect_plan`). Check them in the mission editor and in flight:
  - AttackArea air vs ground-target behaviour;
  - payload IDs 1, 2, 4 and 25;
  - Cover order behaviour.
- The Fighter Pack Reinforcement / Cooldown timers need checking against the historical 20-min F-80 rotation before we document settings as fact.
