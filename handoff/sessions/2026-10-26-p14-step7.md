## What step 7 builds

**`build_air_packs(plan, ctx)`** (signature frozen; step 8 calls it). Per side, DPRK then NATO, over one `SideLogic`, in the §3.0 order:

1. `assemble::assemble_side` → `SideCopies` (places, wraps and points every copy).
2. `clock::build_side` → `trees[0]`.
3. `zone::build_side` → `trees[0]`.
4. `threshold::build_side(side, &copies.areas, …)` → `trees[0]` (reads the consumers and the zone's `pass_subscribers`, so it runs after both front ends).
5. `budget::build_side(side, plan.budget.per_side[side], …)` → `trees[0]`.
6. `assemble::emit_side_logic` → applies `links`, adds `Translator Mission Begin`, `AT s INIT`, `AT s INIT OFF`.
7. **The app's AI country (decision 0023, item 6):** every `Plane` in the side's Sorties tree gets `Country` 602 (NATO) or 503 (DPRK), so the threshold's country-filtered entry trigger never sees the app's own AI. The built-in NATO files carry 601 today (the player country); DPRK files already carry 503. Done here, not in `place_air_sortie`, so the flown probe files stay byte-identical.

A side with no eligible entry adds nothing. The result is one `MapAirPack` whose root is the `Air Tasking` group of §3.0 (four sub-groups: each side's Logic and Sorties), or an empty `Vec` when neither side has an eligible entry (record 0035). The same plan (with its `seed`) and context give identical trees.

**`validate(plan, ctx) -> Vec<AirIssue>`** collects, without building twice where it can avoid it:
- Errors: no enabled valid entry (`rail_only = true`, the only one); a sortie missing from the library; a target on the wrong side; runs outside 1..=6; weight outside 1..=10; budget outside 1..=6 on a side with entries; a template that fails to place or wrap; the threshold spec; `clock::validate_schedule` and `zone::validate_zone` errors per side (they already hold the plain messages); the D30 case when `strategies.ai_counts` is true.
- Warnings: orphaned target (skipped at Generate); sortie out of date for the Map date (skipped); `clock` / `zone` warnings (slot-window cap); D30 (record 0033); each totals limit passed (D36, record 0032); a locale id with different text in two user templates in the pool, naming both files and the id (D41).

**`totals(plan, ctx) -> AirTotals`**: counted by walking the `build_air_packs` output, per side: copies (children of the Sorties group), `Plane` blocks, `MCU_*` blocks (every MCU, the copies' own included; the Complex Trigger counts here), `MCU_CheckZone` blocks. A plan that fails to build gives zeros (`validate` already shows why).

**`preview(plan, ctx) -> AirPreview`** (no build needed; geometry only): per eligible entry a line spawn → target, a spawn point and an RTB point (`mapfighters::rtb_ao_point`, as `assemble_side` uses); per (side, area) a ring at R and a ring at r_in (`derived_timing`); per side with an enabled schedule and at least one eligible `Clock` / `Both` entry, the slot marks first + k·period inside 0–3 h (D29) with the jitter span and quiet %. The spawn point uses the same rule as `assemble_side` (`Clock`: cruise × arrive time; `Zone` / `Both`: the zone spawn distance), through one shared helper so the two cannot drift.

**`frontlines.rs`:**
- `FrontOptions.air_packs: Vec<MapAirPack>`, `Vec::new()` in `Default`; `generate_front`'s "enable at least one layer" check counts it.
- Stamp the air packs after the ground packs and before `aoi_border_group`, with `stamp_rooted_packs`. An empty list changes nothing, so every baseline stays byte-identical.
- `inspect_base_map`: a top-level group whose name starts with `Air Tasking` sets `ImportedBaseMap.air_tasking_found = true` and is dropped. The test must run **before `looks_like_fighter_pack` and `group_has_units`**: the copies hold planes and `Zone IN` check zones, so either would claim them (as an army, the Load path would then also run upstream's `take_strike_missions` over them).
- `MapAirPack` loses its `#[allow(dead_code)]` once `FrontOptions` holds it.

**`src/ui/map.rs`: one line**, `air_packs: Vec::new(),` in the `FrontOptions` literal of `generate_front_file`. Upstream v0.7.0 moved that function from `ui.rs` to `src/ui/map.rs` (`29e1da7`); plan §7 still says `ui.rs`. Step 9 replaces the line with the real call (plan §7). No other UI change; `ui.rs` is not touched.
